# 저장 응답을 보존하는 추가 검토

`review_followup`은 과거 GPT 응답과 별도인 사후 수동 출처 검토다. 생성/검색/자료
기준 시각, 회사 원판정·S/Q/T·순위 및 Radar 최초 실제1건/저장 재검증3건을 바꾸지
않는다. 실제 회사 정보와 원문은 비공개 번들에만 있으며 소스 fixture는 TEST_ONLY다.

회사 주석은 전략·종목뿐 아니라 원래 사건의 발표 표기·사건 날짜·정확 인용 모두에
결속한다. 해당 사건 카드 안에만 표시한다. 뉴스 주석은 사건ID·원래URL·저장 시각에
결속한다. 틀린 대상·인용·시각·위험한 링크는 거부한다. 별도 확인 시각은 저장 시각을
덮어쓰지 않으며 검색 색인/배포 기사 확인을 런타임 직접 수집 영수증으로 승격하지 않는다.

실제 서비스 RadarNews와 ReviewRadar는 같은 watchpoint/impact 표현을 사용한다.
헤드라인 → 한 문장 확인 포인트 → 긍정/부정/중립/혼합/불확실 배지와 범위·조건을
기본 표시하고 긴 보도 내용·기존 해석·출처는 펼친다. 과거 필드 누락은 미평가이며
별도 수동 해석에는 새 GPT 판단이 아님을 명시한다. 기존 terminal 토큰과 한국어
단위 줄바꿈을 유지한다. provider 점수·순위는 재계산하지 않는다.

`build-private-review.mjs --bundle`은 이미 검증된 비공개 번들을 만들 수 있다.
`--password-stdin`은 기존 암호를 숨긴 stdin으로 받아 새 salt/IV로 암호화하며 암호
파일을 만들지 않는다. 기본 `--password-file` 방식은 새 무작위 암호를 비공개로 쓴다.
원본 암호화 자료는 수정하지 않으며 새 후보는 소스 checkout 밖에만 쓸 수 있다.

이번 후보는 로컬·미게시다. 필수 단위·빌드·Pages 보호 확인과 실제 브라우저 검증은
각각 보고한다. 브라우저 연결/프로토콜 제한으로 렌더링을 확인하지 못한 경우 이를
완료로 표현하지 않는다. Site·Library 갱신·운영 main 병합/활성화는 별도 승인 대상이다.
